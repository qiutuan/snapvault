# ADR-0003: 混合检索融合策略 — FTS5 trigram + bge-small-zh-v1.5 + RRF(k=60)

- 状态：已采纳

## 背景
检索必须同时支持：精确关键词命中（画面文字原样搜索）与语义召回（同义改写也能找回）。
中文场景下 FTS 有分词/子串难题。

## 决策
1. **关键词路**：FTS5 使用 `trigram` tokenizer（中文无需分词，任意 3 字符子串可命中），
   查询 <3 字符时退化为 `LIKE %q%` 子串扫描；
2. **语义路**：bge-small-zh-v1.5 对 OCR 文本分块向量化（512 维），sqlite-vec vec0 表 ANN 检索；
   查询侧加 bge 官方指令前缀 `为这个句子生成表示以用于检索相关文章：`，仅查询侧；
3. **融合**：RRF（Reciprocal Rank Fusion，k=60）对两条排序做倒数排名融合；
4. **过滤**：`build_asset_filter` 生成 WHERE 子句（标签/时间/自定义字段/尺寸/置信度/回收站），
   与检索/导出共用同一口径。

## 理由
- trigram 免分词、中文/英文/数字混合都能精确子串命中，量级 10k 行查询 <10ms。
- 向量召回覆盖"文字不同、语义相同"的检索场景；RRF 无需调权即可稳定融合两路排序。
- 融合后按需做过滤，避免把过滤下推到两条检索路径造成口径分裂。

## 已知取舍
- trigram 索引体积约为文本的 2-3 倍（10k 截图 ~ 数百 MB 内，可接受）；
- RRF 对两路都命中的结果天然加权，纯净关键词查询时 FTS 仍居首。
